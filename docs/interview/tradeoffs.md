# 设计取舍

## 采集层

| 选项 | 优点 | 缺点 | 本项目选择 |
| --- | --- | --- | --- |
| `curl_cffi` | 轻、快、Chrome TLS 指纹 | 仍受 IP/反爬限制 | **主路径** |
| Playwright | 动态页面成功率高 | 重、慢、依赖浏览器 | **兜底** |
| Firecrawl | 托管代理/渲染、少运维 | 费用、缓存不可控、字段仍需自解析 | 未来可选 |
| Amazon 专用 API | 字段全、稳定 | 付费/资质 | 生产优先 |
| 手动 capture | 100% 可复现 | 非自动 | **兜底验证** |

结论：4 个 ASIN 用 `curl_cffi` 最划算；Playwright 只在失败时开；官方/第三方 API 是生产方案。

## 存储层

| 选项 | 优点 | 缺点 | 选择 |
| --- | --- | --- | --- |
| SQLite | 零配置、单文件、够用 | 多 worker 弱 | **当前** |
| Postgres | 并发、SQL、生态 | 运维 | 规模化 |
| CSV/JSON | 简单 | 无事务/索引/幂等 | 不选 |

## 交付物

| 选项 | 优点 | 缺点 | 选择 |
| --- | --- | --- | --- |
| Excel 回写 | 用户已有工作流、可审阅 | 格式/大文件限制 | **当前** |
| CSV | 通用 | 用户还要手工合并 | 辅助 |
| BI/数据库 | 可扩展 | 用户迁移成本 | 未来 |

## LLM 位置

| 方案 | 风险 | 选择 |
| --- | --- | --- |
| LLM 直接抽价格/销量 | 编数、不可复核 | **禁止** |
| LLM 只写趋势/建议 | 可能编数字 | **允许 + grounding** |
| 全确定性报告 | 可复核但生硬 | mock 默认 |
| 真实 LLM | 成本/延迟/波动 | 可选，失败降级 |

结论：数字由确定性系统产出，LLM 只组织语言；grounding 失败就降级。

## 范围

| 做 | 不做 |
| --- | --- |

| 缺字段/第三方卖家/CAPTCHA 处理 | 绕过验证码 |

| 离线 demo + 真实页评估 | Kafka/K8s 过度设计 |
| LLM grounding + 降级 | 让 LLM 产数 |
